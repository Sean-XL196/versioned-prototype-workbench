# 账号登录 - 测试规格

> 当前完整有效测试规格。版本：v1.0

## 1. 前置条件

使用当前浏览器打开构建后的 `dist/auth/login.html`。清除本页面 localStorage 后执行首轮测试。

## 2. 核心用例

| ID | 操作步骤 | 预期结果 | 关联需求 |
| --- | --- | --- | --- |
| TST-001 | 打开页面，连续按 Tab，并在密码框按 Enter。 | 初始焦点在账号；焦点顺序符合视觉顺序；Enter 可提交；产品与环境信息可见。 | REQ-001 / REQ-002 |
| TST-002 | 分别提交全空、仅账号、仅密码三种组合。 | 对应字段显示必填错误；首次错误字段聚焦；已有输入不丢失。 | RULE-001 / INT-001 |
| TST-003 | 输入 `demo-admin / wrong-password` 并提交。 | 显示“账号或密码错误”；账号保留，密码清空并聚焦。 | RULE-002 / INT-001 |
| TST-004 | 输入 `demo-admin / Demo@123`，连续点击登录。 | 只进入一次提交过程；按钮显示登录中并禁用；随后显示成功反馈且不真实跳转。 | RULE-002 / INT-001 |
| TST-005 | 切换密码显隐；勾选记住账号后刷新；点击忘记密码。 | 密码值不丢失；刷新后仅账号回显；忘记密码显示原型说明且无网络请求。 | REQ-003 / REQ-004 / INT-002 / INT-003 |
| TST-006 | 分别以 1280px 和 390px 打开页面。 | 表单、品牌信息和操作无重叠；长文本不溢出；页面无横向滚动。 | REQ-001 |

## 3. 回归检查

- [ ] 浏览器控制台无未处理异常。
- [ ] 登录成功和失败均不会产生真实网络请求。
- [ ] 页面刷新后密码字段始终为空。
- [ ] 颜色不是状态信息的唯一表达方式。
